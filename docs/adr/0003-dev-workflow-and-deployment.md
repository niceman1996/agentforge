# ADR-0003：开发流程 —— 单 agent 架构 + 子 agent 批量生产 + 测试门 + 免费部署

- 状态：执行中（2026-10-25，锤大哥完全授权）
- 授权范围：建项目 → spec/ADR → 子 agent 派发（按难度分派，不行就换）→ 开发/测试/部署（免费海外托管，无域名可用 IP/子域名）

## 分工原则（按任务难度派活）

| 活 | 谁干 | 理由 |
|---|---|---|
| 仓库骨架、spec/ADR、共享框架/设计系统、示例计算器 | 主 agent（本人） | 架构决定全局，错误成本最高 |
| 材料数据调研编译（价格/覆盖率/来源） | 子 agent A | 调研+结构化整理，任务边界清晰 |
| 批量计算器页面生产（模板化+SEO 文案） | 子 agent B | 重复性大批量，模板确定后按样本复制 |
| 测试补全与修复 | 子 agent C（失败则主 agent 接管） | 机械性高 |
| 部署与公网验证 | 主 agent | 涉及凭据与外部系统判断 |

- 派单方式：每个子 agent 给自包含 prompt（含文件路径、模板参照、验收标准），产出后主 agent 逐一验收，不合格重派或接管
- 模型选择：按锤大哥指示在 GLM-5.3 / GLM-5.3-flash 间选；当前 harness 的 Agent 派发不暴露逐 agent 模型参数，实际以会话模型执行 + 主 agent 复核兜底（后续若用 workflow 可精确分档）

## 测试门（不绿不部署）

1. `pnpm test`：全部计算公式单测（含取整/边界）
2. `pnpm build`：静态导出成功
3. 冒烟脚本：out/ 全页 HTTP 200 + title/h1/JSON-LD 存在性校验

## 部署决策（免费、海外、IP 可接受）

顺序：
1. 排查本机既有部署凭据（Cloudflare wrangler / gh / netlify / 环境变量）
2. 有凭据 → 直接部署（Cloudflare Pages 得 *.pages.dev 子域名；GitHub Pages 得 *.github.io）
3. 无凭据 → 交付零配置部署脚本 + 5 分钟开通指引（账号注册需邮箱验证，只有锤大哥能做）；同时本地生产服务器保证可用

## 后果

- 流程留痕：所有子 agent 任务与验收记录进 docs/log.md，失败重派也记录
- git 纪律：每个里程碑一次 commit，回滚粒度清晰
